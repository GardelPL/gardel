gardel

State what a routine must do. Prove it. Ship the C.

Gardel is a pure, total language for people and AI agents, built on Tony Hoare's axiomatic semantics. Every routine is a triple {P} C {Q} that Boogie and Z3 prove at compile time. The proof is then erased, so it costs nothing at run time.

Chapter 01 / Foundations

Every routine is a Hoare triple

Gardel's core is Tony Hoare's axiomatic semantics. The meaning of a program is what can be proved about it, stated as a triple {P} C {Q}: if P holds before C runs, then Q holds after it.

Each part of a routine is a part of that triple. The precondition and postcondition together are its contract.

Axiomatic semanticsIn GardelProved by
Precondition {P}requireEvery caller, at the call site
Command CdoNot applicable: this is the code being verified
Postcondition {Q}ensureThe routine, assuming P
Data invariantinvariantEvery routine that builds a value of the type
Termination, for total correctnessvariantEvery recursive routine

Boogie turns each triple into verification conditions and Z3 discharges them. A triple that cannot be proved stops the build, and once proved it is erased.

Where the keywords come from

Eiffel's Design by Contract is one implementation of these ideas in a programming language, and Gardel borrows its readable syntax: require, ensure, invariant, Current and Result. The foundation is Hoare logic, not Eiffel. Eiffel usually monitors assertions at run time, while Gardel treats them as theorems to prove.

module BOUNDED_STACK[A]

representation {NONE}
  items: LIST[A]
  size: NAT
  limit: NAT

create {ANY}

  make(cap: NAT): BOUNDED_STACK[A]
    require
      positive_capacity: cap > 0
    do
      { items = LIST.empty, size = 0, limit = cap }
    ensure
      is_empty: Result.count = 0
      capacity_set: Result.capacity = cap
    end

feature {ANY}

  count: NAT
    do
      Current.size
    end

  capacity: NAT
    do
      Current.limit
    end

  push(x: A): BOUNDED_STACK[A]
    require
      not_full: Current.count < Current.capacity
    do
      { items = Current.items.prepend(x),
        size = Current.size + 1,
        limit = Current.limit }
    ensure
      count_incremented: Result.count = Current.count + 1
      capacity_unchanged: Result.capacity = Current.capacity
    end

  pop: TUPLE[A, BOUNDED_STACK[A]]
    require
      not_empty: Current.count > 0
    do
      ( Current.items.head,
        { items = Current.items.tail,
          size = Current.size - 1,
          limit = Current.limit } )
    ensure
      count_decremented: Result.second.count = Current.count - 1
    end

invariant
  positive_capacity: limit > 0
  size_matches: size = items.length
  within_bounds: size <= limit

end

Chapter 02 / Arithmetic and diagnostics

Overflow is a compile error

Runtime numbers are 64-bit machine values. Contracts reason in unbounded mathematics. The gap between the two is where overflow bugs live, so the compiler makes you close it.

Binary search has shipped with this bug for decades: (lo + hi) / 2 overflows when the sum passes the largest value. Here the build stops, and Z3 supplies an input that breaks it.

Counterexamples are noisy for now

Checks follow evaluation

An obligation holds on the path where its operation runs, so a guard protects what it guards. x != 0 and 10 / x > 1 verifies because the division only runs when the left side is true, and id(if x > 0 then 10 / x else 0 end) verifies for the same reason.

A lambda can be applied to any value of its parameter types, so its body is proved for all of them. It can still use what is known where it is created: fn(y: U64): U64 do y / z end verifies when z > 0 is known at that point. Without that fact, it is rejected with div_by_zero.

Chapter 03 / Totality

Every function ends, and the solver is told how far to look

A Hoare triple on its own says nothing about a C that never finishes. Gardel requires total correctness: it has no loops, and a recursive routine names a variant, a measure that must shrink on every call.

module TREE

representation {ANY}
  | Leaf(value: NAT)
  | Node(left: TREE, right: TREE)

specify {ANY}

  leaves: LIST[NAT]
    variant
      Current
    do
      match Current
        case Leaf(v) then LIST.singleton(v)
        case Node(l, r) then l.leaves.append(r.leaves)
      end
    end

create {ANY}

  from_range(lo: NAT, hi: NAT): TREE
    require
      valid_range: lo <= hi
    variant
      hi - lo
    do
      if lo = hi then
        Leaf(lo)
      else
        let mid = lo + (hi - lo) / 2
        let left_tree = from_range(lo, mid)
        let right_tree = from_range(mid + 1, hi)
        Node(left_tree, right_tree)
      end
    ensure
      non_empty: Result.leaves.length > 0
      in_bounds: forall x: NAT. Result.leaves.has(x) implies (lo <= x and x <= hi)
      has_lo: Result.leaves.has(lo)
      has_hi: Result.leaves.has(hi)
    end

feature {ANY}

  max_value: NAT
    variant
      Current
    do
      match Current
        case Leaf(v) then v
        case Node(l, r) then
          let ml = l.max_value
          let mr = r.max_value
          if ml >= mr then ml else mr end
      end
    ensure
      upper_bound: forall x: NAT. Current.leaves.has(x) implies x <= Result
      attained: Current.leaves.has(Result)
    end

end
examples/tree.gdl

This file uses two kinds of measure. variant Current is structural: the recursive call is on a smaller piece of the value. variant hi - lo is numeric: a NAT expression that gets smaller. A variant may also list several measures, compared in order.

leaves sits in specify, so it is ghost code. Contracts can use it, it is never compiled, and it gives max_value something to promise about: the result is at least every leaf, and is itself a leaf.

Fuel and reveal

An SMT solver can unroll a recursive definition forever, so each definition is guarded by a fuel argument and unfolds one level for each unit of fuel. When fuel runs out, the function is an opaque symbol. The default is 2, which proves tree.gdl as it stands. When a proof needs one more level of a specific definition, reveal leaves raises it for that block.

Chapter 04 / Generic theories

Laws are theorems you prove

A concept names an interface and the laws it must obey. A module that says satisfies must prove each law, and generic code may then rely on them.

concept EQ

  equals(other: Current): BOOL

  law reflexive(a: Current)
    ensure
      refl: a.equals(a)
    end

  law symmetric(a: Current, b: Current)
    require
      ab: a.equals(b)
    ensure
      ba: b.equals(a)
    end

  law transitive(a: Current, b: Current, c: Current)
    require
      ab: a.equals(b)
      bc: b.equals(c)
    ensure
      ac: a.equals(c)
    end

end

Each law in PEANO is a recursive proof. The law's do block is structural induction: a call to the law on smaller values is the induction hypothesis, and variant a keeps it well-founded. The specify {ORD} header says which concept the laws belong to, which matters here because EQ and ORD both have a law called transitive.

module PEANO satisfies ORD, CANONICAL_EQ

representation {ANY}
  | Zero
  | Succ(pred: PEANO)

feature {ANY}

  equals(other: PEANO): BOOL
    variant
      Current
    do
      match Current
        case Zero then
          match other
            case Zero then True
            case Succ(_) then False
          end
        case Succ(p) then
          match other
            case Zero then False
            case Succ(q) then p.equals(q)
          end
      end
    ensure
      structural: Result = (Current = other)
    end

    variant
      Current
    do
      match Current
        case Zero then
          match other
            case Zero then False
            case Succ(_) then True
          end
        case Succ(p) then
          match other
            case Zero then False
            case Succ(q) then p.less_than(q)
          end
      end
    end

Three kinds of equal

A SEQ is a balanced tree, so two sequences holding the same elements can have different shapes. Comparing their structure would be wrong, and if a proof treated it as true, the logic would be unsound. Gardel keeps the three ideas apart.

Chapter 05 / Data at the edges

Bugs are rejected, failures are values

Gardel splits failure in two. If only a mistake in the program could cause it, it is a require, proved at the call site. If the world can cause it, it is a value of type RESULT[E, A] or OPTION[A], and match must handle it.

functions DIGITS

feature {ANY}

  digit(c: CHAR): OPTION[NAT]
    do
      if c.code >= 48 and c.code <= 57 then Some(c.code - 48) else None end
    ensure
      is_digit: Result.is_some implies Result.get <= 9
    end

  two_digits(a: CHAR, b: CHAR): OPTION[NAT]
    do
      match digit(a)
        case None then None
        case Some(x) then
          match digit(b)
            case None then None
            case Some(y) then Some(x * 10 + y)
          end
      end
    ensure
      at_most_99: Result.is_some implies Result.get <= 99
    end

end

There is no null and no exception. digit returns None for anything that is not a digit, and because the proof can see that x and y are at most 9, the multiplication in two_digits needs no extra guard.

OPTION and RESULT also provide map, and_then and unwrap_or, with their monad laws proven in the standard library. get carries a require, so it only compiles where the value is known to be present.

program LENGTHS

        match line_res
          case Ok(line) then

An IO value is linear: it is used exactly once on every path, and it cannot be dropped or captured by a closure. In greeter, each match arm is its own IO action, so the Ok arm opens a second with IO. Why the firewall matters

Pure code gives the same result however it is scheduled, which is what makes the automatic parallelism in chapter 9 safe. For the verifier, each read from the outside is a fresh, unknown value. The only assumption is the boundary guarantee that an Ok holds a valid STRING.

Chapter 07 / Running without end

A server that never stops, written in total functions

A program runs and exits. A reactive program runs until told to stop, without any partial function. Non-termination lives in one place, the runtime's event loop, and your code is two total routines.

-- Run it, then press Ctrl-C.
reactive program REACTIVE_HELLO

feature {ANY}

  step(s: NAT, e: EVENT): STEP[NAT]
    do

The runtime calls init, performs the commands it returns, waits for an event, calls step, and repeats until a step returns Stop. Routines stay pure: they describe commands as values and the host performs them. There is no IO type in a reactive program, and Stop is the only way out. A command that can fail reports it as a later event, and no command blocks the loop.

The state proves itself

Put the state in an opaque module with an invariant. Since only that module can build a value, the invariant holds after init and after every step, however long the program runs. This small game proves the player can never leave the board, whatever keys arrive.

-- The board of the game. It is opaque, so only these routines can build one, and `on_board`
-- holds for every position the game can ever reach, whatever keys it receives.
module TRACK_BOARD

representation {NONE}
  pos: NAT

invariant
  on_board: pos < 5

create {ANY}

  start: TRACK_BOARD
    do
      { pos = 0 }
    end

feature {ANY}

  at_goal: BOOL
    do
      Current.pos = 4
    end

  left: TRACK_BOARD
    do
      if Current.pos > 0 then { pos = Current.pos - 1 } else Current end
    end

  right: TRACK_BOARD
    do
      if Current.pos + 1 < 5 then { pos = Current.pos + 1 } else Current end
    end

  view: STRING
    do
      if Current.pos = 0 then "@...G"
      else if Current.pos = 1 then ".@..G"
      else if Current.pos = 2 then "..@.G"
      else if Current.pos = 3 then "...@G"
      else "....@"
      end end end end
    end

end

        Stop(0, LIST.empty.prepend(Print("You win.")).prepend(Print(board.view)))

        case Key(k) then pressed(board, k)
        case Shutdown then Stop(1, LIST.empty.prepend(Print("Interrupted.")))

      end

A bounded echo server

The same pattern gives a TCP server with a proven limit of 64 clients. admit requires has_room, so step has to check before it accepts. GARDEL_EVENTS replaces the outside world with a script, which is how the run below works with no sockets at all.

-- The live connections of the echo server. It is opaque, so only these routines can build one,
-- and `within_limit` holds after `init` and after every step of an unbounded run.
module SERVER_STATE

representation {NONE}
  live: LIST[CONN_ID]
  limit: NAT

invariant
  within_limit: live.length <= limit

create {ANY}

  make(cap: NAT): SERVER_STATE
    do
      { live = LIST.empty, limit = cap }
    end

feature {ANY}

  has_room: BOOL
    do
      Current.live.length < Current.limit
    end

  admit(c: CONN_ID): SERVER_STATE
    require
      room: Current.has_room
    do
      { Current with live = Current.live.prepend(c) }
    end

  release(c: CONN_ID): SERVER_STATE
    do
      { Current with live = LIST_OPS.filter(Current.live, fn(x: CONN_ID): BOOL do x != c end) }
    end

end

-- Sends back whatever a client sends, to at most 64 clients at once. The limit is proven: see
-- `within_limit` in server_state.gdl. Press Ctrl-C to stop.
--
--   gardelc examples/echo_server --strict
reactive program ECHO_SERVER

feature {ANY}

  init(args: SEQ[STRING]): STEP[SERVER_STATE]
    do
      Continue(SERVER_STATE.make(64), LIST.empty.prepend(Listen(8888)))
    end

  step(s: SERVER_STATE, e: EVENT): STEP[SERVER_STATE]
    do
      match e
        case Accepted(c) then
          if s.has_room then
            Continue(s.admit(c), LIST.empty)
          else
            Continue(s, LIST.empty.prepend(Close(c)))
          end
        case Received(c, data) then
          Continue(s, LIST.empty.prepend(Send(c, data)))
        case Closed(c) then
          Continue(s.release(c), LIST.empty)
        case ListenFailed(_, _) then
          Stop(1, LIST.empty.prepend(Print("cannot listen on port 8888")))
        case Shutdown then
          Stop(0, LIST.empty)
        case _ then
          Continue(s, LIST.empty)
      end
    end

end

What a log does not cover

A log holds everything the program received, in the clear, and has no size limit. On POSIX it is readable by its owner only. A replay shows that the commands repeat, not that their real effects did, such as bytes reaching a client.

One source, three outputs

Parallelism you do not write

Pure code can be evaluated in any order, so the compiler needs no annotation. When two let bindings make independent recursive calls, they fork. This is max_value from chapter 3.

Task depth is capped so that small subtrees do not pay for a fork. On examples/seq_bench.gdl, which builds and sums a balanced SEQ[U64] of 4,000,000 elements on an i9-12900HK, the last roadmap measurement was 196 ms on 1 thread and 66 ms on 20.

Memory

There is no tracing garbage collector. Values are immutable and acyclic, so reference counting frees everything at a predictable point. Counts are atomic, ownership moves on last use to avoid count updates, and a thread-local allocator serves small blocks. Reusing a unique value in place is deferred. Self tail calls become loops; mutual recursion still uses the stack.

Chapter 10 / Organizing code

No imports, one namespace

There are no import statements. Pass the compiler several files, a directory or a wildcard, and they link into one flat namespace, with the prelude already in scope.

  • Each file holds one unit: module, concept, functions, program or reactive program. A file whose name does not match gives warning W0201.
  • Two units with one name are E0102. A dependency cycle across files is E0103, because each proof would trust the other.
  • Nothing may refer to a program: E0104. Entry points are the roots of a run.
  • Every name resolves before anything is verified. An undefined module, type, routine, constructor or variable is E0106 to E0110, at its source line.
  • A private routine, a hidden field or a constructor of a hidden representation cannot be reached from another module: E0113. Opaque state stays opaque.
  • group { A, B } no longer pulls in a library. It is only for modules whose proofs depend on each other in a cycle.

Two layers: one to run, one to prove

SEQ, BIGNAT and STRING split what runs fast from what is easy to reason about. SEQ[A] is a balanced tree with cheap concatenation and natural parallelism, but its contracts are stated over a simple ghost LIST[A] called model. Every operation promises how it changes the model, so a proof never has to think about balance. This is the method of Hoare's 1972 paper on proving data representations correct. For example, concat ensures Result.model = Current.model.append(other.model).

The prelude ships inside the gardelc binary and is trusted during a normal run. gardelc --stdlib --strict re-verifies all 18 source files. To read one, use gardelc --stdlib --inspect SEQ, or write the whole set to disk with --emit-stdlib.
