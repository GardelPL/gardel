Chapter 01 // Foundations

The Eiffel Heritage: Pure Design by Contract

Gardel embraces Bertrand Meyer's Design by Contract principles: routines state preconditions with require, postconditions with ensure, and module invariants with invariant. In Gardel, contracts are not runtime assertions—they are statically proven refinement types that are verified at compile-time and erased for zero-cost execution.

🏛️

Eiffel Design by Contract Reimagined

Gardel adopts Eiffel's crystal-clear vocabulary: module, feature, specify, create, Current, and Result. Unlike traditional languages that bolt contracts on as runtime assertions, Gardel's compiler verifies all preconditions, postconditions, and invariants before emitting code. 
module BOUNDED_STACK[A]

representation {NONE}
  items: LIST[A]
  size: NAT
  limit: NAT

create {ANY}
  make(cap: NAT): BOUNDED_STACK[A]
    require
      positive_capacity: cap > 0
    do
      { items = LIST.empty, size = 0, limit = cap }
    ensure
      is_empty: Result.count = 0
      capacity_set: Result.capacity = cap
    end

feature {ANY}
  count: NAT do Current.size end
  capacity: NAT do Current.limit end

  push(x: A): BOUNDED_STACK[A]
    require
      not_full: Current.count < Current.capacity
    do
      { items = Current.items.prepend(x),
        size = Current.size + 1,
        limit = Current.limit }
    ensure
      count_incremented: Result.count = Current.count + 1
      capacity_unchanged: Result.capacity = Current.capacity
    end

invariant
  positive_capacity: limit > 0
  size_matches: size = items.length
  within_bounds: size <= limit
end
// The compiler generates this formal specification interface via `cargo run -- ... --inspect`
module BOUNDED_STACK[A]
  representation {NONE} -- opaque ADT layout
  create
    Any make(cap: NAT): BOUNDED_STACK[A]
      require positive_capacity: (cap > 0)
      ensure  is_empty: (Result.count = 0)
      ensure  capacity_set: (Result.capacity = cap)
  feature
    Any count: NAT
    Any capacity: NAT
    Any push(x: A): BOUNDED_STACK[A]
      require not_full: (Current.count < Current.capacity)
      ensure  count_incremented: (Result.count = (Current.count + 1))
      ensure  capacity_unchanged: (Result.capacity = Current.capacity)
  invariant
    positive_capacity: (limit > 0)
    size_matches: (size = items.length)
    within_bounds: (size <= limit)
end
// Generated Boogie procedure for formal SMT verification
procedure Verify_push<A>(Current: (BOUNDED_STACK A), x: A) returns (Result: (BOUNDED_STACK A))
  requires BOUNDED_STACK_Invariant(Current);
  requires (fn_count(DefaultFuel, Current) < fn_capacity(DefaultFuel, Current)); // require:not_full
{
  assert {:msg "push::overflow::overflow_add"} in_u64(BOUNDED_STACK_size(Current) + 1);
  Result := BOUNDED_STACK_Ctor(Seq_prepend(x, BOUNDED_STACK_items(Current)), 
                               (BOUNDED_STACK_size(Current) + 1), 
                               BOUNDED_STACK_limit(Current));
  assert {:msg "push::invariant::positive_capacity"} BOUNDED_STACK_Invariant(Result);
  assert {:msg "push::ensure::count_incremented"} (fn_count(DefaultFuel, Result) == (fn_count(DefaultFuel, Current) + 1));
  assert {:msg "push::ensure::capacity_unchanged"} (fn_capacity(DefaultFuel, Result) == fn_capacity(DefaultFuel, Current));
}
// Erased high-performance C11 representation
typedef struct {
    uint64_t head;
    void* tail;
} GardelList;

typedef struct {
    GardelList* items;
    uint64_t size;
    uint64_t limit;
} BOUNDED_STACK;

// All contracts verified & erased -- zero runtime cost
BOUNDED_STACK* make(uint64_t cap) {
    BOUNDED_STACK* res = malloc(sizeof(BOUNDED_STACK));
    res->items = NULL;
    res->size = 0;
    res->limit = cap;
    return res;
}

Chapter 02 // Recursion & Termination

Inductive ADTs, Ghost Models & Opaque Fuel

To prevent non-termination and solver timeouts during verification of recursive functions, Gardel uses a rigorous Fuel Theory (§7.5). Ghost specifications (specify) define mathematical models (e.g., a tree's sequence of leaves), while routines consume bounded fuel until explicitly elevated with the reveal keyword.

⛽

Fuel-Guarded Axioms & Reveal

In SMT verification, recursive definitions are bounded by fuel tokens (ZeroFuel, SuccFuel(f)). When fuel runs out, functions become uninterpreted opaque symbols. The Eiffel-inspired reveal leaves statement elevates fuel to RevealFuel within the lexical block, granting the solver permission to unroll inductive definitions. 
module TREE

representation {ANY}
  | Leaf(value: NAT)
  | Node(left: TREE, right: TREE)

specify {ANY}
  -- Ghost specification function: abstracts tree to a mathematical list
  leaves: LIST[NAT]
    variant Current
    do
      match Current
        case Leaf(v)    then LIST.empty.prepend(v)
        case Node(l, r) then l.leaves.append(r.leaves)
      end
    end

feature {ANY}
  max_value: NAT
    variant Current
    do
      reveal leaves  -- Elevates fuel so Z3 unfolds `leaves`
      match Current
        case Leaf(v)    then v
        case Node(l, r) then
          let ml = l.max_value
          let mr = r.max_value
          if ml >= mr then ml else mr end
      end
    ensure
      attained: Current.leaves.has(Result)
    end
end
// Fuel theory axiomatized in Boogie:
type Fuel;
const unique ZeroFuel: Fuel;
function SuccFuel(f: Fuel) returns (Fuel);
const DefaultFuel: Fuel;
const RevealFuel: Fuel;
axiom DefaultFuel == SuccFuel(SuccFuel(ZeroFuel));
axiom RevealFuel == SuccFuel(DefaultFuel);

// Inductive leaves function unfolds only with SuccFuel
axiom (forall f: Fuel, Current: TREE :: { fn_leaves(SuccFuel(f), Current) }
  fn_leaves(SuccFuel(f), Current) == 
    (if is_Leaf(Current) then Seq_prepend(Leaf_value(Current), Seq_empty())
     else Seq_append(fn_leaves(f, Node_left(Current)), fn_leaves(f, Node_right(Current)))));

Chapter 03 // Real Verification

Real SMT Proofs & AI Counterexample Diagnostics

Gardel does not use shallow concrete fuzzing or sampling. It sends every verification condition to Microsoft Boogie and Z3. When a contract fails, Gardel translates Z3's raw internal SMT model into an AI-friendly JSON diagnostic with concrete counterexamples, preconditions, and candidate lemmas.

🔍

The Classic Midpoint Bug Detected

In binary search, (lo + hi) / 2 overflows if lo + hi > 2^64 - 1. Gardel automatically emits 64-bit overflow assertions (in_u64(lo + hi)). Z3 synthesizes exact counterexamples (e.g. lo = 1, hi = 18446744073709551615) and halts compilation. 
module MIDPOINT_BUG

feature {ANY}
  midpoint(lo: NAT, hi: NAT): NAT
    require
      ordered: lo <= hi
    do
      (lo + hi) / 2   -- ⚠️ SMT Prover detects 64-bit arithmetic overflow!
    ensure
      in_range: lo <= Result and Result <= hi
    end
end
module MIDPOINT_SAFE

feature {ANY}
  midpoint(lo: NAT, hi: NAT): NAT
    require
      ordered: lo <= hi
    do
      lo + (hi - lo) / 2  -- ✅ Formally verified: no overflow possible
    ensure
      in_range: lo <= Result and Result <= hi
    end
end

Chapter 04 // Generic Mathematical Theories

Concepts, Mathematical Laws & Orderings

Gardel uses concept to specify abstract algebraic interfaces, accompanied by mathematical law blocks. In Gardel, concept laws are not tests—they are quantified multi-trigger SMT axioms. A module stating satisfies ORD must prove every law before compilation succeeds.

⚖️

Decoupled Behavioral Equivalence & Total Order

Phase 1 resolved the SMT Leibniz identity contradiction by redefining concept EQ as an equivalence relation (reflexive, symmetric, transitive). concept ORD refines EQ introduces strict ordering and totality laws, verified on modules like PEANO. 
concept ORD refines EQ
  less_than(other: Current): BOOL

  law irreflexive(a: Current)
    ensure
      not_less_than_self: not a.less_than(a)
    end

  law transitive(a: Current, b: Current, c: Current)
    require
      a_lt_b: a.less_than(b)
      b_lt_c: b.less_than(c)
    ensure
      a_lt_c: a.less_than(c)
    end
end

module PEANO satisfies ORD
representation {ANY}
  | Zero
  | Succ(pred: PEANO)

feature {ANY}
  less_than(other: PEANO): BOOL
    variant Current
    do
      match Current
        case Zero then
          match other
            case Zero    then False
            case Succ(_) then True
          end
        case Succ(p) then
          match other
            case Zero    then False
            case Succ(q) then p.less_than(q)
          end
      end
    end
end
// Emitted Multi-Trigger SMT Axiom in Boogie:
axiom (forall a: PEANO, b: PEANO, c: PEANO ::
  { fn_less_than(DefaultFuel, a, b), fn_less_than(DefaultFuel, b, c) }  // Multi-trigger
  (fn_less_than(DefaultFuel, a, b) && fn_less_than(DefaultFuel, b, c)) ==> 
  fn_less_than(DefaultFuel, a, c));

Chapter 05 // Effect Containment

The Linear IO Monad & Purity Firewall

Gardel maintains 100% mathematical purity in ADT modules. Side effects are strictly confined to program entrypoints using the with IO construct. The compiler enforces an affine/linear consumption firewall: IO values can never be dropped, duplicated, or leaked into pure functions.

🔒

Strict Linearity & The Program Boundary

Standard ADT modules cannot invoke with IO. Only a program with main(args: LIST[STRING]): IO[EXIT_CODE] may interact with the outside world. This guarantees that all functional code remains Church-Rosser confluent and deterministic. 
group { SEQ, BIGNAT, STRING, OPTION, GREETER }

program GREETER

feature {ANY}
  main(args: LIST[STRING]): IO[EXIT_CODE]
    do
      with IO
        name <- IO.read_line
        IO.print("Hello, " + name)
        IO.exit(0)
      end
    end
end
-- ⚠️ Compiler rejects IO inside pure module:
module PURE_BOX
representation {ANY}
  val: NAT
feature {ANY}
  bad_effect: IO[EXIT_CODE]
    do
      with IO  -- ❌ Phase 4 (IO Boundary Violation): pure modules cannot use with IO
        IO.print("illegal side-effect")
        IO.exit(0)
      end
    end
end

Chapter 06 // The Compiler Pipeline

One Source, Four Verification & Execution Targets

A single Gardel file compiles to four specialized backends simultaneously: SMT verification conditions for Microsoft Boogie, higher-order proof lemmas for Dafny, massively parallel fork-join code for Bend v2, and zero-cost portable C11 with OpenMP.

Boogie Direct SMT (.bpl)

Low-level verification conditions targeting Z3. Fuel theories, variant disjointness, and overflow checks.

Dafny Higher-Order (.dfy)

Formal inductive datatypes, recursive function definitions, ghost model refinement, and concept law lemmas.

Bend v2 Massive Parallelism (.bend)

Interaction Combinators target compiling to CUDA and Metal GPUs with automatic divide-and-conquer parallelism.

C11 Native C & OpenMP (.c)

Clean, portable C11 code compiled with GCC/Clang. Contract erasure for bare-metal runtime efficiency.
